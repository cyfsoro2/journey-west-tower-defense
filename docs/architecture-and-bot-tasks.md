# 原型架构与 Bot 开工任务

状态：设计草案。以下接口是协作约定，尚未实现；实际开发时由战斗系统负责人维护接口和集成。

## 一局游戏如何运行

状态流：开始界面 → 角色放置 → 第 1 波 → 升级三选一 → 第 2 波 → 升级三选一 → 第 3 波 → 胜利；唐僧血量降至 0 时立即失败。升级选择期间暂停战斗，选定后开始下一波；胜负页面允许重新开始。

建议目录：

```text
index.html             页面与入口
src/main.js            初始化、输入与游戏循环
src/combat.js          单位、移动、攻击、阻挡和波次
src/upgrades.js        升级池、抽取与效果
src/ui.js              界面、信息展示和操作反馈
src/config.js          地图、角色、妖怪与波次数值
```

采用浏览器 ES 模块时，通过本地 HTTP 服务运行；运行方式由开发完成后的 README 记录。游戏循环使用时间间隔 `dt` 更新状态，渲染与状态更新分开。地图、路径和各单位实际数值先采用可试玩的占位配置。

## 模块边界

- `combat` 拥有游戏状态和推进权：放置、波次、单位更新、伤害、死亡和胜负。统一暴露给界面只读的当前状态及玩家动作入口。
- `upgrades` 返回可选择的升级及其效果定义；选择后由战斗模块统一应用到状态。每次从尚未达到叠加上限的升级中不重复抽取，候选不足 3 项时展示全部可选项并允许继续。
- `ui` 接收状态并渲染，向游戏入口发送“开始、放置、选择升级、重新开始”动作；不直接修改战斗状态。
- 接口名称与对象结构在开工时由 Bot 1 与其他 Bot 共同确认，避免多人同时修改同一份战斗代码。

战斗更新顺序示例：

```text
若唐僧血量 <= 0：进入失败并停止更新
若当前正在战斗：
  按波次计时生成妖怪
  更新定身、持续伤害与存活状态
  推进未被阻挡的妖怪，处理近战与防御角色攻击
  妖怪到达唐僧后攻击唐僧
  若唐僧血量 <= 0：进入失败
  否则若本波生成结束且没有存活妖怪：
    第 3 波进入胜利；其他波进入升级选择
```

## Bot 1：战斗系统与集成

```text
请阅读 README.md、docs/game-design.md、docs/sprint-1.md 和本文档，使用 HTML5 Canvas 与原生 JavaScript 实现三波塔防原型。你负责 src/main.js、src/combat.js、src/config.js 和最终集成。

唐僧在地图中央，有 100 生命；妖怪从四个方向沿路径接近并攻击。玩家在指定格子放置悟空和八戒，悟空攻击范围内最近目标并造成范围伤害，八戒近战并阻挡敌人。实现生成、移动、攻击、血量、死亡、波次、胜负及重开。提供给 UI 的状态与玩家动作接口，并与升级模块确认效果应用方式。升级选择时暂停战斗。

使用几何图形占位。把波次、角色与妖怪参数放在配置中；提供本地运行说明。完成后实际跑一局，验证放置、移动、攻击、阻挡、波次、胜利、失败及重新开始，并列出已知问题。升级与界面由其他 Bot 负责，请在接口稳定后集成，不覆盖他人文件。
```

## Bot 2：升级与数值

```text
请阅读 README.md、docs/game-design.md、docs/sprint-1.md 和本文档，负责 src/upgrades.js 的肉鸽升级模块，与 Bot 1 先确认输入输出和效果应用接口。

实现升级池和波间不重复三选一，支持叠加上限和候选不足的情况。初始升级包含金箍棒扩大悟空攻击范围、紧箍咒短暂定身、三昧真火持续伤害；清楚定义触发方式、持续时间、数值和叠加方式，数值放在可调整的配置中。模块只返回选择和效果，不自行推进波次或直接改写战斗状态。

验证抽取不会出现重复选项或超过上限，每种效果被接入后有可观察变化。交付接口、参数、验证方法及需要 Bot 1 集成的事项；不要修改战斗模块。
```

## Bot 3：界面与测试

```text
请阅读 README.md、docs/game-design.md、docs/sprint-1.md 和本文档，负责 src/ui.js 的界面与试玩检查，与 Bot 1 先确认读取状态和发送动作的接口。

实现开始、角色选择与放置提示、血量和波次、波间升级选择、胜负结算和重新开始。界面需显示升级效果，点击后清晰反馈选择结果；升级期间不允许重复选择。使用简单清晰的占位视觉，确保常见桌面窗口可操作。界面通过动作回调与入口通信，不直接改写战斗状态。

联调时实际体验从开始到胜利、失败和重新开始的流程，检查升级选择、血量和波次显示。记录复现步骤与实际结果，交给对应模块负责人修复；不要修改战斗或升级模块。
```
